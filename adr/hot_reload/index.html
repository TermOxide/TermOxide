Architecture Decision Record

Hot reload

Forty decisions about how an app author's logic gets swapped into a running TUI without losing state, without hanging the host, and without either side's logs corrupting the terminal — with what was drafted, live-tested, and rejected along the way.

SAVE           file watcher (debounced) ──▶ rebuild logic

REBUILD        cargo build --target wasm32-unknown-unknown
               success ──▶ load (D2.2 checks signature)   failure ──▶ keep current generation (D5.4)

PER CALL       host ──(IPC, D4.2)──▶ subprocess ──▶ wasmtime instance
               state crosses as postcard bytes (D3.2), host never decodes it (D3.3)
               fuel/epoch bounds the call (D5.1); a trap discards the generation (D5.3)

EVERY FRAME    build_view ──▶ styled lines ──▶ host renders (D2.3 — guest never touches the terminal)

The three questions this record answers

QuestionAnswer
Which transport — native dylib, wasm, or hot-lib-reloader? wasm. All three were drafted and live-tested to the same contract; wasm won on failing safe on a function-signature mismatch and bounding a guest's infinite loop, with no cooperation required from the guest, neither of which either native form gets for free. Domain 2
Does the sandbox mean giving up filesystem, network, or stdio? No. Those properties come from wasm's execution model, not from capability restriction — WASI is configured permissively by default. Domain 7
How do you catch a hot-swapped module that hangs or crashes? Two independent layers. Fuel/epoch interruption bounds a call with no guest cooperation; a flat subprocess-level timeout catches everything that isn't a wasm call at all. Domain 5

Status

Recorded 30 September 2026, following the same process the styling ADR used: three candidate transports drafted to an identical contract, live-tested (not just compiled) including real crashes, hangs, restarts, and a genuine concurrency stress test, before any comparison was trusted. Superseding a decision means adding a new entry rather than editing an old one; the rejected alternatives are the record's main value and should survive.

The implementation-facing companion is SPEC.md, which states the same decisions as requirements without the reasoning.
