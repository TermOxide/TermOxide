Architecture Decision Record

The styling system

A signal-driven, JSX-like TUI framework in Rust. Forty-eight decisions about how style is written, resolved, inherited, animated and finally turned into bytes — with what was rejected and why.

COMPILE TIME
  style!{…}  ──▶ const Style   (partial, tri-state)

ONCE PER TREE BUILD
  component fn ──▶ nodes in slotmap arena

PER CHANGE          (targeted write — no tree rebuild)
  ① merge      slot default ◀ theme ctx ◀ passed style ◀ state
  ② inherit    node.inherited: Rc<Inherited>

PER FRAME
  ③ animate    target ──interpolate──▶ presented
  ④ layout     presented[Layout|Both] ──▶ taffy ──▶ integer edges
  ⑤ paint      presented[Paint|Both] + TerminalProfile ──▶ cells
  ⑥ diff       cell buffer diff ──▶ CUP + SGR bytes

The three questions this record answers

QuestionAnswer
Which syntax — CSS, SCSS, React Native, StyleX? None of them. A typed Style value with a style! literal macro. StyleX's merge semantics are adopted; its compiler is not. Domain 2
Where does the styling layer live? Nowhere separate. No compilation stage and no stylesheet artifact — an effect writes a value into a live node. Domain 10
Adopt the CSS spec, or write a TUI styling standard library? Neither wholesale. Flexbox semantics via Taffy; four units; deliberate divergence on box model, borders and overflow. Domain 5
